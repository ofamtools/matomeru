# Changelog

Generated by o-inventory from the snapshots in ~/hub/inventory: one entry per snapshot, newest first, only the concepts that changed. Every line but Commits is derived from the diff; `fixed:` lines quote `fix:` commit subjects.

## Unreleased

### Visual-line d at once, path chooser opens on known (ochazuke, unreleased)
- fixed: `V j d` on Tasks deletes the selected tasks after one confirm; it took `V j d d`, the task's normal `d d` making visual-line's `d` wait (ochazuke `sequence-inherit drop`).
- added: `V j d` on Panes kills the selected panes after one confirm (pane `visual-line` `d` → `pane.kill`, its normal rows read after it); `d d` still kills the focused pane in normal mode.
- changed: the path chooser opens on `known` through `PathChooserSpec.Source` instead of stepping `chooser.next-source` after opening (the workaround is gone), and the known source keeps the old chooser's rule of cutting the branch and project columns before the path (`ChooserSource.Keep`).
- opt-out: ochazuke's `sequence-inherit keep` for the old `V j d d`.

### ochazuke v0.47.0: visual-line, the path chooser, tree zoom
- changed: ochazuke v0.47.0 (from v0.42.0). Framework settings are declared at startup; mtm declares none of their names, so nothing moved.
- changed: `V` on the Panes, Work (tasks) and Inbox lists enters ochazuke's `visual-line` mode (badge `VISUAL-LINE`); `j`/`k`/counts extend, the rows' own keys (`m`, `s`, `x`, `d d`, `Y`) act on every selected row through visual-line's extends of normal, `esc`/`V` leave. ochazuke's `visual.list marks` keeps the older selection in normal mode.
- changed: copy mode judges a mode by its selection shape (`SelectionShape`, SC-05), not its name: `isVisualMode` is gone and `copy.select {shape}` enters `SelectionMode(shape)`.
- added: directory fields are folder path parameters (`{type: path, path: dir}`): `project directory PATH`, `project edit-directory --to`, `project new --dir` (a missing folder is still attached and flagged), `dirs add-base PATH` and the schedule form's `dir`, whose field opens the path chooser. Every folder chooser lists mtm's `known` directories (the Directories page's) and the `project`'s own directories (the default first) after ochazuke's `browse`, `recent` and `typed`; `recent` is mtm's `dir_recent`, newest first.
- added: setting `directory-chooser` for what asks for a project's directory (`c`, attach, move, a directoryless pin): `path` (default: the path chooser opened on `known`; `tab` cycles the sources; no `browse…` row, the `browse` source replaces it), `path-remembered` (the path chooser on the source last used) or `known` (the known-directory chooser with `browse…` to the Directories page, as before).
- added: the outline gets ochazuke's tree zoom (`z +`, `z -`, `z 0`, `h` past the top steps out; breadcrumb above the rows). fixed: a Panes section sizes its tree with `Tree.Height`, so a zoom's breadcrumb or a filter line no longer windows its last row.
- opt-out: `directory-chooser known` for the old directory chooser; ochazuke's `visual.list marks`, `tree.zoom off`, `forms.single-path form`.

### Renames open selected (ochazuke v0.42.0)
- changed: ochazuke v0.42.0. Every input answers the standard editing keys (`alt+backspace`/`ctrl+backspace` kill a word back, `alt+d`/`ctrl+delete` a word forward, `super+backspace` to the line start, `alt`/`ctrl`+arrows by word, `super`/`meta`+arrows to the line ends). `i` on an outline row (project, task, pinned root) opens the line with its text selected, following ochazuke's setting `rename.select` (default on): typing replaces it, `end`/`ctrl+e` keeps it and moves to the end, `esc` leaves.
- changed: the rename form (pane `r`, session `r`, saved-pane rename) sets `RecordSpec.Rename`, so it also opens with the name selected; typing replaces the name with no `ctrl+u` first.
- opt-out: set `rename.select` to false in `settings/ochazuke.json` for the old behaviour (cursor at the end).

### Drive: terminal, exec, api
- added: `drive` as data: on harness profiles (`harnesses.json` `"drive"`, default `terminal`) and on schedules' command rows (`"drive"`, default `exec`, the headless run they always were). `exec` runs the program as a plain process (`internal/drive`: under `nice`, its own process group, stdout and stderr streamed line by line, the exit code the outcome); `terminal` opens a tuios pane running it; `api` is reserved for the API pane (plans/agent-apis.md): validated and accepted, refused as "drive api is not available yet" when a run uses it.
- added: `command.run` (`mtm command run "LINE" [--drive exec|terminal|api] [--dir D] [--label L]`): a command line from the palette or the CLI, exec by default. New noun `run` with `list`, `show`, `rerun`, `stop`, `forget` and the Runs page (after Schedules): the TUI's last 32 exec runs, their state and exit code, the detail streaming the output; `r` reruns, `d d` forgets. Each run is an ochazuke job labelled with its title, so the jobs ticker shows it while it runs.
- added: per-run overrides: `agent.start`, `project.launch` and `task.launch` take `--drive` (a harness with drive `exec` runs its argv as a run, the prompt on stdin, or last for `prompt: arg`); `schedule.run-now --drive` changes the drive for that run only; `schedule add|edit --drive` stores it on a row. A schedule run's record carries `drive` when it was not exec.
- changed: a command run in a missing folder fails with "folder X: not a directory" (was the exec error).
- opt-out: nothing changes unless a row or a run names a drive; the Runs page is a new tab (ochazuke has no way to hide a page yet).

### Agent view: turns, terminal, both
- added: settings `agent.view` (`turns` default, `terminal`, `both`) and `agent.view-split` (50; 10..90): where the Panes detail opens a pane and, for `both`, the percent of the width the turns take beside the pane's screen.
- added: harness profile block `view` (`{"open": "both", "split": 60}`, own file `internal/harness/view.go`, a pointer merged by field, `null` removes it, validated at load); it beats the settings.
- added: `pane.view turns|terminal|both|default [--split N]`: the pane's own view, stored by window id (new table `pane_views`), beating the profile; `default` drops it. Listed panes carry `view` and `view_split`. No default key (`v` is free on pane rows).
- changed: a pane whose view differs from the last one applied opens on its own tab; between panes of one view the chosen tab stays, so with no view configured the detail behaves as before. The `both` split is drawn only when chosen.

### Turn cards: keys by availability (card-steps follow-ups)
- changed: a turn's state is its verbs' availability (SC-22 removed): `turn.open` is available on a closed turn, new `turn.close` on an open one. `l` is `turn.open` then `ochazuke.timeline.enter` (open, then step inside); `enter` is `turn.open` then `turn.close` (it now closes an open turn; before it ran `turn.open` again); `h`/`left` are `turn.close` then `turn.back`. The `turn-closed`/`timeline-card-open` guard rows are gone; `turn-closed` and new `turn-open` are verb guards, judged on the nearest turn on the focus path.
- added: `turn.review` (mark the turn reviewed, a shell turn reads its output, without opening it); a card opened by the timeline's own keys runs it once (`syncOpenedCards`, which ran `turn.open` before).
- changed: on an open tree row `l` no longer reruns `turn.open`; the tree's own `l` answers.
- fixed: inside a card the turn's rows answer (`R` rereads the turns), and the footer reads `y copy step`, `Y copy turn` instead of `timeline-body.copy`. Needs the ochazuke release where the timeline body sits under its card (branch `card-steps2`).
- added: the tree style reads an edit's tool call as a diff, as the cards do.

### Live panes replay into the terminal.engine emulator
- changed: a live pane's stream replays into an emulator made by ochazuke's terminal engines (`ocli.NewEmulator`, `ocli.EmulatorFrame`) instead of `charmbracelet/x/vt` directly. The default is `tuios-vt` (`tuios.dev/vt` v0.3.2, MIT, the emulator tuios itself draws the pane with, so its snapshots repaint exactly); `x-vt` is the old emulator.
- added: setting `terminal.engine` (`tuios-vt`, `x-vt`; `ghostty` only in a build with `-tags ghostty`, refused with the reason otherwise). A change applies to streams opened after it; an open pane picks it up on its next attach.
- Dependencies: `charmbracelet/x/vt` is no longer a direct dependency (ochazuke keeps it for the `x-vt` engine); `tuios.dev/vt` v0.3.2 and `tuios.dev/progstatus` v0.1.0 (MIT) come through ochazuke. Needs the ochazuke release with `cli.Emulator` (branch `vt-swap`).

### Prompt box on any pane
- added: every live pane gets the prompt box, agents of any harness (Codex had none) and plain shells or terminals. How it delivers comes from the harness profile's new `promptBox` block (`harnesses.json`, beside `session`): `{"deliver": "queue"}` for the built-in agents (send, queue and interrupt as before, never typed over a waiting question) and `{"deliver": "send", "submit": "enter"}` for a pane with no profile and no agent (the text as one paste, bracketed where the program asks for it, then Enter; `"submit": "none"` leaves it typed). A terminal's box shows `[send]` or `[type]`, has no modes (ctrl+t stands aside) and reads "type into the pane".
- added: the box is drawn below the Screen tab's screen too (not while a live terminal or copy mode is shown); `i` on the pane row writes there. The Turns tab keeps its box.
- added: settings `prompt.on-terminals` and `prompt.on-screen` (both on) opt out of the box on terminals and on the Screen tab.
- changed: `pane.prompt` and `turn*.prompt` (`i`) are available only where a box is drawn for a live pane, so `i` stands aside on an exited pane; the `pane-prompt` guard is now the verbs' availability, not a guard row. `turn-prompt.mode` is available on an agent's box only.

### Actions over a visual selection
- fixed: in a visual selection (`V`), a verb that asks (`m` associate, `s` status or snooze, `d d` on projects and tasks) changed only the first row. It now asks once ("Move 3 rows to", "Delete X and 2 more?") and applies the answer to every selected row; other row verbs already ran per row. One notice reports the run.
- changed: the outline's `x` and `s` are the task row's own verbs (`outline-task.toggle`, `outline-task.status`), so over a selection they change every task and one `u` undoes them all; `outline.toggle` and `outline.status` stay.
- needs: ochazuke v0.36.0.

### Turns
- added: harness `session` sources (`harnesses.json`, built-ins for `claude` and `omp`): each listing reads the harness's own records of the session a running agent writes now and uses it in place of the id tuios reports (kept as `reported_session`). The Turns tab and a side's folder follow a `/clear`, a resume or a fork on the next listing, without `R`. Claude: `~/.claude/sessions/<pid>.json`, tied to the pane by the process's `TUIOS_WINDOW_ID` and checked against its start time; a pane whose claude only attaches to a background-daemon session takes the folder's one running session that no pane holds. omp: `~/.omp/agent/terminal-sessions/<tty>`, while omp runs on the pane's terminal; an omp pane tuios reports no harness for becomes an omp pane. Several possible sessions are a notice (`session_note`), never a guess.
- added: `tty` on listed panes (from tuios `list-windows`).

### Schedules
- added: prompt schedules. A schedule row has a kind: `command` (gh-signals, slack-signals) or `prompt`, which starts an agent with the row's prompt the way `agent.start` does (an ordinary agent pane: Working while it runs, the inbox when it is done or waiting). The agent fields are `harness`, `model`, `effort`, `fast`, `permission-mode`, `project`, `task`, `dir`, `into` (`new`: a new pane each run; `pane`: queue the prompt in the open pane named `pane`, which tuios types when the agent rests and never over a question, else start one) and `pane`.
- added: timing by the clock. `when` is `every 30m`, `daily 09:00`, `mon,wed,fri 09:00,17:30`, `weekdays 8:30`, `cron 0 9 * * 1-5` or `never`; `start` and `end` (dates, end inclusive) bound it.
- added: `schedules.catch-up` setting (`none` default, `once`) for runs missed while mtm was closed; a row's own `catch-up` wins. The built-in signal rows are `once`, as before.
- added: `schedule.add`, `edit`, `duplicate` (`--as`), `delete` (confirms; stored rows only). Rows added from mtm are stored in the new `schedule_defs` table and merge over the built-ins and `schedules.json` by name; editing a built-in stores a copy, deleting the copy brings the built-in back. In the TUI, `n` on the Schedules page records an empty prompt row (off) and opens its form, written as you type; `E` opens a row's form, `d d` deletes it.
- added: a run's history records what it launched (pane, harness, model, settings, argv, prompt status); `schedule.history` and the detail link the pane.
- added: harness setting rows take `flags`, the argv that sets the setting at launch; Claude's `permission-mode` launches with `--permission-mode`. A setting with only a command is typed before the first prompt.
- added: migration: matomeru-old's prompt schedules in the `schedules` table are imported once into `schedule_defs`, off.
- changed: the Schedules page's columns are `when` and `runs` (were `every` and `command`).

### Status segments
- added: cpu, ram and the free space of the data directory's volume ride the rule under the tabs (ochazuke status segments, `sysstat`), on by default. Opt out with `status.segments.cpu`, `status.segments.ram`, `status.segments.disk`, or `status.segments` for all; `status.segment-order` holds the order (`segment move`). `segments.json` beside `settings.json` adds or changes rows; `segment list|show|enable|disable|toggle|move|refresh` from the palette and the CLI.
- added: a mounted extension's catalog segments (verb-sourced) are added as `<extension>-<id>`, each with its own setting.
- needs: ochazuke v0.36.0.

### Panes and tasks
- added: `pane.pick-task` (`t` on a pane row, off the footer): a task picker over the page. The pane's current task or project comes first, so `enter` keeps it. Open tasks follow, the pane's project's first and the most recently updated first, then projects with no task, then `unassociated`. Typing filters; a query that matches nothing offers `new task "<title>" in <project>`; `esc` changes nothing.
- added: the prompt box opens that picker as soon as it sends (the send is already on its way and does not wait). Setting `prompt.after-submit`: `pick-task` (default), `pick-task-if-unassociated`, `none`.
- added: `pane.unassociate`; `task.associate --pane ID` and `project.associate --pane ID`, the reverses of `pane.associate --task` / `--project`, sharing its handler. A pane is named by row id or window id; a pane mtm has not listed is still recorded.
- changed: the pane detail header says `task <title>` for a pane with a task, and `unassociated` for an agent with no task or project.

### Panes page
- The left side is three lists stacked top to bottom. **Waiting · Review** (top) is the inbox queue: waiting panes (needs input), errored panes, panes with an unread finished turn, then outside items (o-gh, Slack, `mtm action-item add`), oldest first in each; every project's, whatever the pin. **Panes** (middle) is every other pane, grouped by `panes.group` and following the pin. **Working** (bottom) is agent panes while they work, oldest submission first; every project's. Terminals never leave Panes. j and k spill between the lists; each scrolls on its own and its title counts its rows (`+N more` when they do not fit).
- A queue row of a pane's signal is its action item standing for the pane: the detail and preview show the pane, `enter` attaches it (it used to fail with "no URL to open"), and the inbox keys (u, x, X, s, t, c, m) act on the item.
- The row under the cursor stays in its list while its state changes, and moves once the cursor leaves it; rows keep their order within a list across refreshes.
- The page is titled **Inbox**; the old Inbox page, every action item in every state, is titled **Items** (S on it still opens Schedules). Page ids are unchanged (`page.open panes`, `page.open inbox`). `I` opens the merged page.
- The page opens on the top list when it has rows (its first row at start), else on the middle list; a focus in the detail or a live pane stays where it was.
- The header counts what needs you and what works: `panes (N) · Q need you · W working`. When the list is narrow, hints go first, then the counts shorten (`Q need`, `W work`) and then go; `panes (N)` stays.
- New settings: `panes.sections` (signal=section; default `waiting=queue`, `errored=queue`, `unread=queue`, `working=working`), `panes.queue-order` (default `waiting`, `errored`, `unread`, `outside`), `panes.section-layout` (`budget`, the default, or `thirds`), `panes.queue-percent` 25, `panes.panes-percent` 60, `panes.working-percent` 15.
