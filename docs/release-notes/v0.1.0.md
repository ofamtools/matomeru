# mtm v0.1.0

The first release of Matomeru (`mtm`), a terminal workspace for coding agents. It gathers projects, tasks, notes, live agent panes, their turns and your reviews in one TUI. It is built on [ochazuke](https://github.com/unixsuperhero/ochazuke) v0.51.0 and runs its agents in panes of a [TUIOS](https://github.com/Gaurav-Gosain/tuios) daemon that it starts for itself (`mtm-daemon`). Every action in the TUI is also a command (`mtm task new --title …`, `mtm project pin`, `mtm catalog`), so scripts and other tools can drive it.

```sh
go install github.com/unixsuperhero/matomeru/cmd/mtm@v0.1.0
mtm --version
```

Requires Go 1.26 or newer and TUIOS.

## Inbox

- `I` from any page opens the Inbox: action items from any source, unread first. The title row shows the unread and open counts (`inbox 2/5`).
- On an item, `enter` opens its URL, `u` marks it read or unread, `s` snoozes it, `x` archives it and `X` restores it. `t` and `c` promote it to a todo or a task, `m` moves it to a project, and `d d` deletes it.
- Tools add items with `mtm action-item add --source … --url … --title …`. The command is idempotent on the source and key, so a poll that runs again refreshes its row. Items need no project: an item without one is unassociated.
- mtm's own panes add items while the TUI is open: an agent waiting for input, a finished turn, or an errored agent. Each kind has an `inbox.signal.*` setting that turns it off.

## Work

- The Work page lists projects on the left, and the selected project's header, task table and detail on the right. Pinning a project (`P`, `mtm project pin`) filters every project-owned list. With no pin, all projects show.
- Tasks have the statuses todo, active, blocked and done. `x` toggles done, `s` chooses a status, and `enter` opens the record editor, which saves each change as you make it. It has no save key.
- `O` edits a project's tasks and subtasks as an outline. `tab` and `shift+tab` turn a project into a task and back. `T` opens the todo outline on any page.
- `N` opens a quick note on every page. Notes, reviews, directories, saved panes and Vim sessions each have their own page.
- The Context page collects files, directories, commands, links and prompts that mtm extracts from agent output as it arrives. `ctrl+a c` in a live pane picks one to copy, open or insert.
- Keys mean the same thing on every row: `n` new, `d d` delete, `r` rename, `i` edit, `m` move, `L` launch an agent, `q` close.

## Panes

- Panes is the first page: a tree of sessions and panes beside a detail with tabs for Turns, the live Screen, activity and the transcript.
- The terminal leader (`ctrl+a`, the `terminal-leader` setting) goes before keys typed into a live pane. After the leader, the app's normal-mode keys work as they do outside live mode. The leader also opens side panes (`v` side Vim, `t` side terminal), zooms (`z`), opens copy mode (`[`), opens the context picker (`c`) and labels every pane with a hint (`f`). Leader `?` lists these keys.
- Panes can be starred (`*`, next starred pane with `` ` ``), picked (`pane.pick`), saved as records you can reopen, and renamed. `W` goes to the next pane that needs input.
- `pane.view turns|terminal|both` sets what a pane's detail opens on. The defaults come from `agent.view` and `agent.view-split`.
- Harnesses (claude, omp, codex and your own in `harnesses.json`) are data. `L` launches an agent through a harness chooser. `command run` and the Runs page cover plain processes.

## Turns

- The Turns tab rebuilds an agent's turns from the history journal: each turn shows the prompt text and the full answer, and nothing is cut. `mtm setup` installs the turn-capture hooks for each harness.
- Turns are drawn as cards (`turns.style cards`, or `tree`), with a status glyph and tone (`turns.status-glyph`, `turns.status-border`). You can step inside a card, and `h` folds an open answer. `turns.thinking` and `turns.tools` show or hide thinking and tool calls, and their `-open` settings choose whether those start open.
- The agent's settings line (model, effort, permission mode, context, cost) sits above the turns, with verbs that change those settings.
- Reviews keep one row per pane, with the pane's turns as the detail.

## Prompt box

- A prompt box below a pane's Turns tab, and below its Screen tab, writes to the pane. `enter` sends. `ctrl+v` pastes images and files as attachments, and `alt+o` picks a context item into the box.
- Settings:
  - `prompt.after-submit-mode` (`normal`, or `insert` to keep typing) sets the box's mode after a send.
  - `prompt.after-submit` (`pick-task`, `pick-task-if-unassociated`, `none`) sets whether mtm asks which task or project the pane belongs to.
  - `prompt.on-screen` and `prompt.on-terminals` remove the box from the Screen tab and from shell panes.

## Schedules

- Schedules run commands on an interval while the TUI is open. The built-in `gh-signals` (`auto`) and `slack-signals` (off) feed the Inbox. `schedules.json` adds schedules or changes them.
- Prompt schedules start an agent, or queue a prompt into a named pane, at the times given by `--when` (`every 30m`, `weekdays 8:30`, `cron …`). `--start` and `--end` bound a schedule, and its catch-up setting decides what happens to runs missed while mtm was closed.
- The Schedules page (`S` on the Inbox) runs a schedule now, turns one on or off, sets an interval, and adds, edits and deletes schedules. Runs go under `nice`, never overlap, time out, and back off after failures.

## Extensions

- The Extensions page lists the family tools on `PATH` (`o-<name>`) as available, registered, stale or missing. `n` registers one, `L` refreshes it and `d d` removes it.
- A registered tool's catalog is mounted: its pages become tabs and its nouns and verbs work in mtm's palette and CLI. Each extension gets its own database under `<data>/ext`. The Docs page comes from `o-md` this way.
- `mtm mcp serve` lets an agent in a TUIOS pane drive mtm over MCP. `mtm mcp config claude` prints the config entry to add.

## `:set` and settings

- `,` opens the Settings page, which writes `settings.json` as you change values.
- `:set` on the palette line (`set scrolloff=5 nowrap`, `set opt?`, `verbose set opt?`) changes values for the current session only, with completion of names and values. `setting.write` and `settings.write` save session values to the file. `setting.revert` and `settings.revert` drop them. `settings.revert` now asks before dropping values. `settings.review` steps through each session value to write or revert it.
- `mtm settings get|set|apply|diff` are the CLI.

## Vim keys

- Motions follow Vim: counts (`10j`), `g g`/`G`, `ctrl+d`/`ctrl+u`, `ctrl+e`/`ctrl+y` line scrolls, `/` to filter any list, `V` visual-line selection on lists, tables and trees (verbs act on every selected row), `"` registers, `q` macros, `.` dot-repeat and `u` undo.
- Pane commands use the `ctrl+w` prefix (`ctrl+w w`, `ctrl+w >`/`<`/`=`). `g y` opens the yank history and `q :` opens the command line on its last command.
- Copy mode on a live pane is a read-only buffer with Vim motions, search, `v`/`V` selection and `y` yank.
- Every key is a row in a bindings file. `mtm bindings list`, `mtm bindings check` and `~/.config/matomeru/bindings.json` show and change them. Function keys are never bound.

## Docs and help

- `?` opens the key help for the current focus.
- In the palette, `help` or `h` (`docs open index|settings|bindings`) opens the generated reference in a read-only viewer. It shows the settings and key rows of the running build, with your own `settings.json` values and `bindings.json` rows marked (`docs.show-config`).
- `mtm --version` prints the version, the commit and the ochazuke version. `make install` from a checkout adds the version and commit to the binary.
