# mtm, unreleased

Notes for the next release (v0.2.0). CHANGELOG.md is generated by o-inventory; these lines are the hand-written part.

## Panes

- Fixed: an agent pane whose subagent rows are running or waiting on their own work now sits in the Working list even when its own state is idle or done. New setting `panes.subagents-working` (default on) turns it off. The `panes.sections` error for a state word now points at `panes.working-states`.

- Fixed: with `directory-chooser` set to `known`, a path typed into the chooser (`/tmp`, `~/proj`, `./x`) is answered at once by a typed source, through ochazuke's `ChooserSource.Claims` and `chooser.claim-source` (default on) as in the path chooser: it lists the folder and its matching folders, enter picks it, and a path that is not there says `no such directory` instead of closing silently. Plain words still match the known directories.

## One notifier for inbox items and reminders

- New Slack and GitHub action items notify on any TUI page, from the inbox's startup/five-second reload. `action-item notify-due` uses the same worker headlessly. A persisted first-run baseline suppresses old items; per-item two-minute claims prevent competing processes from sending twice during normal delivery. More than five new items are one summary.
- `notify.channel` defaults to `terminal`; `notify.commands` defaults to the string `"[]"`. Reminders use these senders unless their existing overrides are explicitly set. `reminders.notify` now defaults to empty, meaning follow the shared channel. An explicit `reminders.notify-commands`, including `"[]"`, remains an override.
- `inbox.notify` defaults to `new`, with `off` disabling delivery and notices. `inbox.notify-sources` defaults to `["slack","gh"]`. `action-item add --notify` and the standard `notify` prop bypass only the source filter. `inbox.notify-in-app` defaults to true and holds unread notices without taking focus or opening a modal.
- `notify.failures` defaults to 3 consecutive schedule failures. A failure raises one forced-notification item keyed `schedule-failing:NAME`; success archives it, and a new failure cycle reuses the row. Set the threshold to 0 to stop raising these items.
- Retire the independent `inbox-notify` schedule row before using the built-in notifier. No owner config is changed automatically.
- Real desktop popup permissions and OSC 9 passthrough through tuios remain unverified. A crash between external delivery and its receipt can duplicate a notification after the claim expires.

## Agent writes and retained archives

- Changed: reads and recoverable writes are open, including settings, bindings, actions, themes, project structure, schedules and setup. Stored-data deletes refuse agents. `pane.kill` and `session.kill` require confirmation; extension registration and removal stay owner-only. Owner rights rows still override verb defaults, and protected gate settings remain owner-only.
- Added: standard `archive` and `restore` for task, note and context-item records, with history attribution and undo. Default views hide archives and task subtrees without cascading flags. `list.hide-archived` defaults to true; false includes archived rows. Standard lists expose the `archived` saved filter. Old records read as live without an archive migration.
- Changed: `agents.owner-task-props` defaults to `status` and `archived`; existing explicit owner configuration is preserved.
- Fixed with ochazuke v0.86.0: archived saved filters refill app-owned task trees; empty archive-capable lists declare their row noun before any record exists; palette restore resolves archived `t1` even when live `t10`/`t11`/`t12` share its prefix. All three archive regression stories run without skips.
- Compared with Vim: not applicable to retained workspace records.

## Daily reminders

- Added: a store-backed `reminder` collection on Schedules with local time, weekday subset, enablement, archive/restore, and daily checkoff history. `x` toggles today's checkbox; `enter` opens history; `n` opens the form. `reminders.show` defaults to true.
- Added: `check`, `uncheck`, and `toggle` accept past local dates and record the actor. Previous dates keep their scheduling rules when time or days change. Today's checkbox changes at midnight without a reset job. Agent checkoffs default to `allow`; destructive deletion refuses agents.
- Added: notifications from the running TUI only, at startup and every minute, sharing atomic per-date claims with manual `reminder notify-due`. Failures remain visible through errors and `notify-status` and retry on the next tick. No service is installed.
- Added: reminder notifications use shared `notify.channel`, sanitized OSC 9 through Bubble Tea's output queue or argv-safe local `osascript`. `reminders.notify` defaults to empty and can override the channel; an explicitly set `reminders.notify-commands` overrides the shared argv commands.
- Added: persistent due notices with the effective checkoff key, without a focus change. `reminders.notify-in-app` defaults to true; `notice clear` dismisses.

## MCP agent guidance follows the lane and doc workflow

- Changed: `mtm mcp serve`'s About and agent rules now tell agents that mtm is the only MCP server they need (o-lane, o-questions, o-cmds, o-md and o-git through `run`), to track work as o-lane lanes in mtm projects associated with their pane, to change an mtm task's status only when asked, and to put findings in an o-md document linked with `document_report`; notes are for short jots. See docs/MCP.md "What agents are told".
- Changed: project creation, metadata and structural edits are declared `allow` for agents. Project deletion remains destructive and owner-only by default.

## Saved task filters (ochazuke v0.65.0)

- Added: task catalog defaults `mine` (`made-by=owner`), `agents` (`made-by=agent`) and `all` (unfiltered), shared by Work task rows and editable outline task rows. The framework owns prop matching, ancestor context, the strip, picker, cycle keys `z ]` / `z [`, and standard task list `--filter NAME`. `/` search still combines with prop conditions. No app-side maker predicate remains.
- Migrated: `tasks.made-by` becomes `work.tasks-filter`, the Work startup default (`all`). A valid old file value is rewritten once, preserving unrelated settings and preferring a canonical value if both exist. `tasks.made-by` remains a readable/writable deprecated alias until the release after v0.2.0. Applying/cycling a filter is session state, without changing that startup default. `mine` means owner exactly now; unknown makers are included by `all`.
- Opt-outs: framework settings `list.filter-strip` and `list.filter-cycle` default true; false hides the strip or disables cycling respectively.
- Added: notes record their own `created-by` actor on create across CLI, MCP `task_note_add` and TUI, including the agent identity. `made-by` exposes owner / agent / unknown. Existing notes read unknown; the schema migration raises the version without rewriting any content. Editing preserves provenance, and agents cannot replace it.
- Added: the note noun declares the same `mine` / `agents` / `all` saved filters. The Notes list, standard `note list --filter NAME` and the selected task's notes in the outline use the framework filtering engine. Each list retains its session filter across data refreshes.
- Added: a notes pane below the tasks outline, using ordinary note rows and all their existing actions. `ctrl+w w` walks panes. Vertical list motion remains clamped in modals by ochazuke v0.65.0; a separate skipped story records that framework gap. Opt out with `notes.task-pane=false` (default true); the framework strip/cycle opt-outs apply here too. The formerly skipped note-maker gap story now passes, with stories for both cycle directions in the modal and Notes page.
- Compared with Vim: `:filter` (`:help :filter`) restricts command output by text pattern; ours filters typed props. `CTRL-W w` (`:help CTRL-W_w`) walks panes in both. Named filters and cycling: n/a, no Vim counterpart.

## Running subagents under their pane

- Added: an agent pane's running subagents are rows under its row in the pane list (the Panes tree, Needs you or Working, wherever the pane's row is): description and type, the status word in its class's colour (statusWords) and its age. A finished subagent drops off at once; a failed or killed one stays for `panes.subagents-linger` (default `30s`), then drops. The rows are read from the pane's harness log off the loop (`panes.read-activities`), only the spawn calls, their results and the task notifications, from where the last read stopped; a Claude pane has them, omp and Codex panes none (their logs name no subagents).
- Added: the `pane-child` noun: `open` (`enter`: the pane's Turns tab with the card of the call that started the subagent selected; the focus stays on the list) and `copy` (`y`: description, type and agent id). j/k pass through the rows; a selected row shows its pane's detail; a row that drops off while selected leaves the cursor on its pane.
- New settings: `panes.subagents` (`active`, the default, or `off`: no rows and no reads) and `panes.subagents-linger` (default `30s`).
- Fixed: a pane whose row moves between the lists takes its child rows along; a child row left behind in the old list made the rebuild fail ("parent must come before it").

## Turns cards colour every status word by its class

- Fixed: a task notification whose summary words its end its own way kept its status word muted: a background command's `completed (exit code 0)`, a monitor's `stream ended`, `failed with exit code 144`. Every status word on a Turns card (a turn's, a notification's, the journal's) is now looked up in one table of words (`statusWords`, `cmd/mtm/turn_status.go`) by its longest leading phrase, falling back to the notification's own status field, and drawn in one of four classes: needs you (`state.needs-input`, ?), working (`state.working`, ● and ◐), done (`state.done`, ✓) and bad (`state.errored`, ✗ and ⊘). A word in no row stays muted. The word keeps its tone on a muted or unfocused card.
- Changed: a stopped or killed task (⊘) is bad now, red with an alert border, not grey: it did not finish.
- Fixed: a failed task whose summary does not start with "failed" ("didn't finish before the previous session ended") reads `failed: didn't finish …`, and "failed with exit code 1" keeps its space.

## Extension nouns are namespaced

- Built on ochazuke v0.58.0. A visual-line delete over several rows names the first row and counts the rest ("Delete task write the brief and 1 more?"), with what they orphan; v0.57.0 said "Delete task true?".
- Renamed: an extension's nouns mount as `<ext>.<noun>` (ochazuke's `cli.Namespace`, as every family host names them), no longer `<ext>-<noun>`: `md-doc` is `md.doc`, `json-doc` is `json.doc`, and so on for every mounted noun. Their verbs keep their names: `md-doc.send-notes` is `md.doc.send-notes`.
- Added: a noun no other mounted extension has also answers to its bare name (`item` for a `fake.item` no other extension shares), in the palette, the CLI (`mtm item list`), keys and `bindings.json`, and is drawn by it. A name two extensions share (`doc` for `json.doc` and `md.doc`) gets no bare alias; the palette offers both full names (ochazuke `palette.noun-tails`). The namespace words work too: `mtm md doc list`, `:md doc list`.
- Deprecated: the old spelling `<ext>-<noun>` stays an alias of the new noun until after v0.3.0. A `bindings.json` row, an `actions.json` row or a script that names it still runs, with one notice (`md-doc is an old name of md.doc (renamed in v0.2.0; removed after v0.3.0)`); `mtm bindings check` names each row spelled the old way.
- New setting `extensions.noun-names` (Settings › Extensions › General): `namespaced` (the default, above) or `legacy` (`<ext>-<noun>` only, no aliases, as before). Changing it remounts the extensions.
- An extension whose name ochazuke reserves as a namespace (a framework noun's short name such as `list` or `settings`, `app`, `ochazuke`) keeps the dashed spelling, with a notice.

## Old flags of the standard-verb aliases work again

- Fixed (Keep actions): `task status --id T --status X` and `review status ID --status X` run again, as `--value` does, with one notice (`task.status: status is an old name of value`); they had stopped with "task.set has no parameter status" when the aliases became the standard `set`. Deprecated: `--status` on these aliases is removed after the next mtm release (ochazuke v0.58 `ParamAliases`, as `--starred` on `pane star` and `context-item star`).
